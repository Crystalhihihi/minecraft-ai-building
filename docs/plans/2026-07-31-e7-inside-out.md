# E7:从里到外造楼(2026-07-31 立项)

> 触发:E6 发现"内外同病"(生成器空壳 / 逐块进不去)。用户定调:**不要参考图,从里到外——内部确定了再修外形**。
> 模型:全线 k3-256k(客户端 config 已配 agent_model;E6 的 v4-flash 数据不作质量锚点)。

## 管线(三段,每段 = 生成器 + 机器验收门)

1. **里(布局)**:功能 spec(房间清单/门/楼梯/净空)→ 布局生成器排房间+走道+楼梯井 → **walkability 机器验收**:flood-fill,2 格净空,从大门必须能走到每个房间与每件家具前。**不过门,不进下一段**。
2. **外(结构)**:墙体/屋顶生成器——**窗位由内部房间决定**(窗对床/桌/梯间,不在立面拍脑袋);屋顶形态跟体量;楼梯朝向全部过 `patterns/stair_orientations.md` 规则 → 结构验收:墙体闭合、无悬空、朝向合规。
3. **饰(立面)**:三层深度(立柱/窗套/檐口)+ weathering 掺比 → 用户目检。

验收哲学:机器卡"能用"(连通/净空/闭合/朝向),人卡"好看"。E6 的 diff 环退役(无参考图),留作精灵树等有参考专项。

## 首题

两层带阁楼小住宅:3 室(主卧/次卧/书房)+ 厅 + 楼梯 + 走廊,脚印 ≤15×12。
- 场地:bounds `x[560,619] z[300,359] y[60,120]`(虚空,远离既有建筑)
- 锚点:甲板西北角 (570, 78, 310),大门朝南(+z)
- 家具 v1 只 3 类:床(靠墙,侧留 1 通道)/桌(邻窗)/书架(靠墙)

## 会话编排

- **会话 A(里)**:任务书=功能 spec+布局规则 → 生成器排布局,建甲板/隔墙/门/楼梯/基础家具,停 → 我跑 walkability,不合格 /aichat 反馈迭代,合格进 B
- **会话 B(外+饰)**:任务书=结构+立面规则 → 外墙/屋顶/窗(对位)/修饰,停 → 渲染目检
- (B 视情况拆"结构"与"饰"两会话;先跑通再拆)

## walkability 验收器(`scratch/phase9/walkability.py`)

- 输入:区域 box + 大门坐标 + 必经点(各房间中心/家具前)
- 扫描:bridge get_block 全量(v1 区域 ~10k 调用/分钟级,可接受;量大再下沉 mod 端点)
- 通行模型 v1:可站立格 = 非实心(空气/装饰白名单/门)且下方有支撑(实心/楼梯/台阶);四邻移动 y∈{-1,0,+1},目标格 2 格净空;楼梯视为可站立可支撑
- 输出:可达格数、不可达必经点清单、分层 ASCII 图

## 风险

- 布局生成器是首个难点(房间邻接/门对齐/楼梯井)——允许会话 A 多迭代,验收器数据说话
- 家具模式库薄:首题 3 类起步,后续按 B8 扩
- 窗位由内定可能与立面节奏冲突——先内后外,饰段微调
