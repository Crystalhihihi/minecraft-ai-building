## B1. 多 agent 集群(重开时需"agent 集群调研讨论 + 写 plan")

**背景**(2026-07-29 讨论定调):用户强烈倾向多 agent 协作;定论是**杂交架构**——

**模型分工(2026-07-30 终版:Kimi 原生梯队,放弃外部供货商)**:

| 岗位 | 模型 | 依据 |
| --- | --- | --- |
| 规划/分解(planner) | K3(Kimi Code managed) | 选址/拆任务/风格一致性 |
| 终审/视觉验收 | K3 | 英雄资产审美终审(GDMC 证据:审美不外包给小模型) |
| 执行搬砖(worker) | **K2.7 Coding**(managed,同套餐) | 用户套餐内自带,image_in+thinking+tool_use 全有,可自渲染自检;零新增成本、零外部限流 |
| 短平快杂务 | K2.7 Coding Highspeed | 高速变体 |
| ~~外部小模型~~ | 放弃 | SiliconFlow 券级限流风暴实测不可用于生产;百炼/Minimax/OpenRouter 免费档同属共享池病;按量付费 vs 套餐内自带,后者胜 |

历史记录(2026-07-30 实测):SiliconFlow Qwen3-VL-32B(视觉 19.3s 合格)、Qwen3-Coder-30B(结构化全对)曾入选,但券级限流 429 频发且无缓存豁免,一晚上 7 次掐断 E0,判生产不可用。工人能力本身已验证合格(读任务书/风格卡/propose/放置零错误/渲染自检)。

- **形态**:1 个规划 agent(强模型 K3:选址分区、风格一致性、任务拆分、终审)+ N 个 worker agent(便宜模型 Qwen/DeepSeek/Ollama 本地:执行规格明确的结构)+ 每 worker 自己的渲染自检环 + mod 侧确定性验收
- **成本逻辑**:总 token 会增加,但 80% 的活挪到便宜 20-50 倍的模型上,总账省 5-10 倍;买的是墙钟时间和上下文隔离(避免单体长建造上下文膨胀/压缩丢细节)
- **可行性前提**:**模式库 + 风格卡片越厚,能下沉给小模型的比例越高**(设计工作→填参数+执行)
- **小模型禁区**:看图自检(需多模态)、审美裁决(GDMC 证据:GPT-4 端到端审美仅 38% 满意度)、规划分解
- **mod 侧功课**:并发会话锁(替代全局单 agent,顺手修双起 bug)、每 agent 独立 SiteGate 边界(空间不重叠=天然防冲突)、每会话收件箱路由
- **Kimi Code 机制**:多 provider(`kimi provider add`,OpenAI 兼容,DeepSeek/Qwen/Ollama 均可接)+ sub-agent 分模型 + AgentSwarm;具体配置方式重开时验证
- **第一笔**:A/B 对照实验——同一个小房子,K3 单干 vs K3规划+Qwen执行,比成本/耗时/质量三组数,数据说话
- **顺序铁律**:先单 agent 盖好精灵树(单建筑终验),再上集群——multiplier 不能替代 competence

## B2. 建筑群与道路(整体延后)

- 建筑群配合、道路网络(坡度惩罚 A* 寻路,GDMC 赢家做法)、区域规划
- 选址算法增强:高斯滤波选址评分(GDMC 2025 冠军做法)——沙盒脚本即可,不动 mod
- **多建筑终验**(用户定):以《奥日与黑暗森林》精灵之树为中心,周边装饰性建筑+自然景观组成大型景观;单建筑终验=精灵树本体(需用户提供参考图,AI 多模态照图施工)
- **精灵树是算法任务,不是建造任务**(用户 2026-07-29 定调):光凭 AI 想象建模"吃几万块都出不来"——必须走**程序化树木生成**:空间殖民(space colonization)/ L-system / 递归渐细弯曲枝干 + 板根/树冠团簇/发光脉络参数化,作为一个独立的"调研+开发+对着参考图迭代"专项来做;本质是模式库哲学在最难目标上的应用——模式即算法
- **巨树=超大型建筑同类问题(用户 2026-08-05 定调)**:巨型结构撑不住不是因为结构,是因为**细节密度跟不上体量**——大白墙放大 3 倍就成灾难。原则:**表面每大 4 倍,细节层级多一层**——L 体块分解(次体块/翼楼/退台,把大体积拆成有节奏的小组合)→ M 巨构语法(巨柱/台基层/飞扶壁,构件尺寸随体量放大)→ S 肌理密度(现有 facade_depth/accent 层,已覆盖)。现有卡全部按中小体量校准,巨量化需要 profile 随体量缩放 + 体块分解先行;精灵树验收必须同时考算法和细节层级

## B11. 参数受控变形 + 风格卡白名单化(2026-08-05 讨论定调,先记下)

- **核心**:多样性=各轴取值相乘;16 张风格卡现在是"固定配方"(roof 写死 gable 等单值),要改成**合法取值空间**(roof/accent/weathering/profile 各给白名单),AI 在白名单内选
- **变形三层管**:①枚举层(profile/palette/材质组)随便变,安全区;②seed 层最优雅——同卡同参换 seed,受控可复现零漂移;③数值层禁止 LLM 手填,变形需求做成生成器新参数(如 facade_depth gradient)
- **变形边界**:可动密度/点缀/掺比/profile/seed/预算梯度;不可动结构句法(屋顶形式/开间节奏/承重逻辑同楼必须一致)

- **环境轴**(地形/邻接/朝向进推导链)单独立项,走"生成器+真实灌入验证"路线,不信本地自检(B10 教训)

## B13. 多样性总路线(2026-08-05 swarm 四路分析定稿)

**① 数学审计结论**:组合数 10¹³ 级,从来不是瓶颈;**瓶颈在剪影层**——生成器只产矩形平面+体量轴单一,剪影差异仅 ~30-60 种,连造 30 栋即"脸熟"。语料对照:真人同风格差异主贡献=平面/体量形状>屋顶>尺寸;材质反而是低方差轴(已覆盖好)。增厚优先级:Ⓐ平面形状生成器(L/T/U/凹凸组合,按凹凸率 0.1~0.43 分档采样)Ⓑ体量轴放开(层数 1-3/顶型放宽到 3-4 种每风格/屋顶占比采样含 ~20% 平顶/耳房配楼)Ⓒ风格卡 16→24 次要项;**微观 seed 层停止投入**(已饱和且肉眼不可辨)

**② 抽签器(抗 AI 偏好)**:风格卡加 `lottery` 字段——每轴枚举带权 variant(权重:语料可定的标 `source: gc:类目:n=数`,拍脑袋的标 `prior`+`calib: TODO`)+`rules` 处理卡内二阶耦合;卡是原子的,抽"选哪张卡+卡内开关",不跨卡拼字段(洋葱顶+中式不可能发生,因为它不在白名单)。接入点:访谈后建造前,抽签结果写 task.json 新增 `build_order` 字段,与 task 同权威、默认不可推翻(硬冲突可在 plan.md 申请改一个轴)。防软抵抗:验收器抽查关键轴(柱距/屋顶型可机器验)。聚落级加配额去重(同 variant 不连出 3 次)。成本≈0(纯 Python)。抽签器落 lottery_log.jsonl 攒校准数据

**③ 人味清单**(治"无菌感"):clutter_pile(杂物堆)/wear_path(踩出来的土径)/clothesline(晾衣绳)/chicken_coop(鸡窝)/wall_weathering 加 patch_pct(异材补丁)/accent 加 lone_item(破例孤件)/桌面杂物/脚手架在建痕迹。**判别原则(防"刻意的随意")**:每栋只上 1-2 种;痕迹必须锚定功能(柴堆在壁炉同侧);影响 ≤5% 方块;异材同风格;"去掉后建筑还成立但略空"=合格

**④ 重复性实验方案**(验证 mode collapse):plan.md 捷径——只跑到 plan.md 落盘就终止,消耗为整栋 1/8。中性提示词连跑 N=8,A 组自由发挥 vs B 组抽签任务单。指标:风格卡众数占比/尺寸 CV/材质 Jaccard/平面 IoU;实锤阈值:①众数≥7/8 ②CV<10% ③Jaccard>0.7 ④IoU>0.5,中 3 项=强坍缩。预算 ~1.1M(含 2 栋真造校验)或 560k 纯 plan。风险:plan 多样但建造收敛会高估多样性,2 栋真造校验堵这个洞

**实施序**:白名单化(lottery 字段)→ 平面形状生成器 → sampler+build_order 接入 → 人味卡 2-3 个 → 重复性实验 A/B
